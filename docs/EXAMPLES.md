# 依頼の例

自然な言葉だけでも使えます。スキル名を明示すると手順を選びやすくなります。

## 会議を仕事の更新につなげる

```text
example-ai-pilotの定例メモを整理して。
会議前の状態と比べて、何が決まり、何が未決なのかを明確にして、
議事録・現在地・タスクを更新して。人数を増やす話は提案だから確定扱いしないで。
```

入力：sources/raw。出力：meetings、current、tasks、decisions。練習のときはREADMEの再現手順でsandbox-outputに保存します。

## 社内報告の前工程

```text
example-ai-pilotの状況を部内報告にしたい。
原本と現在地から材料を整理し、重要な数字と判断事項が分かる1枚のHTML、
5枚のスライドの構成案をoutputsに作って。まず構成案までで止めて。
```

入力：原本・現在地・タスク。出力：summary.html、report-outline.md、review-checklist.md。構成に合意してからPowerPoint等への展開を別途頼めます。

## 経費の提出準備

```text
サンプルの2026-10の経費を整理して。
規程と明細と証憑メモを照合し、コピペ表、証憑対応表、確認が必要な項目を作って。
私用は除外、根拠不足は申請候補へ混ぜず別欄へ。提出はしないで。
```

サンプルの申請候補は交通費640円と3,100円で合計3,740円です。2,200円の書籍は領収書不足で確認待ち、1,200円の買い物は私用として除外します。証憑メモは本物の領収書ではないため、候補を整理できても提出できる状態ではありません。

## 雑な音声相談

```text
なんか毎月の報告が面倒で、何からやるかいつも忘れる。
材料はinboxに入れた。まず何が揃ってて何が足りないか整理して、できるところからやって。
```

start-workで目的・材料・判断点を整理し、必要な場合だけまとめて質問します。

## 続きから再開

```text
handoffs/latest.mdを読んで、my-first-projectの未完了の作業を続けて。
古い前提がないか、案件の現在地と原本の更新日も確認して。
```

## 学びを手順へ反映

```text
今回、提案を決定と勘違いしたところを学びとして残して。
同じ処理で再発しないように会議の後処理スキルを直し、両ツールのコピーを同期して。
他の仕事にまで過剰な確認が増えないようにして。
```

## 月1回の整理

```text
ルールの重複と、期限切れの現在地、手順の正本とコピーのずれを点検して。
復元可能な整理は進めて。削除・安全設定の変更・共有が必要なら具体案を先に作って。
```
