# 記録と学び

- ファイル名は原則 `YYYY-MM-DD-topic.md`。日時の欄にはタイムゾーンも記す。原本の既存名は不用意に変えない。
- `current.md` は最新状態の正本。各重要事項へ根拠を付け、最終更新日を入れる。履歴は `decisions.md` と作業ログに残す。
- `tasks.md` にタスクID、内容、担当、期限、状態、根拠を記録する。未指定の担当・期限は `未確認`。
- タスクは `未着手 / 進行中 / 待ち / 完了 / 取消`。完了には完了根拠を付ける。期限切れだけで取消にしない。
- 作業終了時に `logs/YYYY-MM-DD-topic.md` と案件別の引き継ぎを残し、`handoffs/latest.md` を入口として更新する。
- 引き継ぎには目的、読んだ原本、完了、未完了、必要な判断、次の操作を残す。会話全文や秘密値を保存しない。
- 学びは「起きたこと → 次回の対処 → 適用範囲 → 根拠」で短く書く。未検証なら候補として残す。
- ローカルのGit履歴を運用する場合は依頼の範囲を確認し、`git add .` で一括投入せず対象を選ぶ。push・公開は別の確定操作。
- フォルダ移動後は目次と根拠リンクも更新する。削除より保管を優先し、重複と古い指示は月1回程度の整理で減らす。

## Decision・Workflowの追加記録

- 詳細な判断記録は `templates/decision-record.md` を使い、選択肢、却下理由、判断主体、再検討条件、根拠を記載する。元の `decisions.md` は索引のまま維持する。
- 複数案件に共通する判断基準だけを `knowledge/decisions/INDEX.md` へ登録する。案件の許可が自動的に他案件へ及ぶわけではない。
- 作業手順の新規提案は `workflows/drafts/`、結果と反省は `workflows/evaluations/`。review・承認・回帰評価を経てからSkill化する。
