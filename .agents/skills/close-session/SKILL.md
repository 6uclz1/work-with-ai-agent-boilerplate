# 作業の区切りを残す

1. 対象案件のcurrentとtasksを実際の成果物・原本に照らす。作業したことと、成果が検証済みであることを区別する。
2. templates/work-log.mdに沿ってlogsへ、目的、変更ファイル、確認結果、未完了、重要な判断を記録する。会話全文や秘密値は保存しない。
3. templates/handoff.mdに沿って案件別のhandoffsファイルを作る。読む順序と次の一手を具体的なパスで残す。latest.mdは案件別の入口を残す一覧として更新する。
4. 学びを「現象／次回の対処／範囲／根拠」で案件のlessonsへ残す。横断して使える確認済みのものだけknowledge/lessonsへ移す。
5. 再現する作業なら該当の.agents/skills/SKILL.mdを最小限に改善する。全業務共通の約束はrulesへ書く。未検証の仮説は候補のまま残す。
6. 安全設定や確認範囲の変更が必要なら具体的な差分と理由を作り、未承認で適用しない。
7. スキルを変更したらscripts/sync_skills.pyでコピーを同期し、scripts/check_workspace.pyで点検する。Pythonがなければ管理対象の対応ファイルを手動で比較・コピーする。
8. ローカルGitの記録を依頼されている場合は、対象ファイルを選んでコミットする。外部pushはしない。
9. 最後に成果物、確認、未完了、次に必要な人間の判断を短く伝える。
