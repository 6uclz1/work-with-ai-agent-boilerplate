# 横断して使う意思決定記憶

案件固有の採用決定は、従来どおり `projects/<name>/decisions.md` にIDと要約を残す。詳細（検討した代替案・根拠・却下理由・承認者・再検討条件）が必要な場合、`templates/decision-record.md` に従って案件内の `decisions/<ID>.md` に保存する。

複数案件で参照する**汎用的な判断基準**だけをこのディレクトリの `records/` へ昇格させ、[INDEX.md](INDEX.md)へ登録する。元案件へのリンクと適用範囲を必須にする。

- proposed（提案）、accepted（確認済み）、rejected（不採用）、deferred（保留）、superseded（置換済み）を区別する。
- acceptedには人間の明示的な決定・日時・根拠が必要。AIの提案を勝手に採用しない。
- 判断変更時は既存文書を削除せず、後継IDで参照をつなぐ。
- 判断の記憶は権限付与ではない。過去に委任された仕事でも新たな外部操作は独立して許可確認する。
